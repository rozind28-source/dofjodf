# Crypto Screener — self-hosted

Real-time скринер криптовалют по мотивам [cryptoscreener.app](https://cryptoscreener.app/):
карта рынка, таблица-скринер с 20+ метриками, **свечные графики по каждой монете**,
плотности стакана, алерты. Данные берутся напрямую с бирж по WebSocket —
без посредников и подписок.

**7 бирж подключено по умолчанию** (12 коллекторов: спот + фьючерсы), включая две децентрализованные:

| Биржа | Фьючерсы | Спот |
|---|---|---|
| Binance | ✅ | ✅ |
| Bybit | ✅ | ✅ |
| OKX | ✅ | ✅ |
| MEXC | ✅ | ✅ |
| Gate.io | ✅ | ✅ |
| **Aster** (DEX) | ✅ | — (спота нет) |
| **Hyperliquid** (DEX) | ✅ | — (спота нет) |

Есть **фокус-режим**: одна биржа + один рынок + top-N монет по вашему фильтру
(по умолчанию 50, перепроверка раз в 15 секунд) — стримится только то, что
реально отображается. Замер на живых биржах: подписок 450 → 50, а сетка из
9 графиков грузится за **0.13 c вместо 21 c**. Подробности и цифры —
в разделе [«Фокус-режим»](#фокус-режим-одна-биржа--один-рынок--top-n-по-фильтру).

Рынок переключается тумблером **«Фьючерсы / Спот»** в сайдбаре — он применяется
ко всему сразу: скринеру, карте, плотностям и сетке графиков. У DEX спота нет,
поэтому тумблер для них показывает только фьючерсы, а чипсы бирж без выбранного
рынка гаснут, чтобы по клику не получалась пустая таблица.

Проверено живыми запросами: 6020 инструментов, $165B оборота, спред цены BTC
между биржами 0.06%. DEX-биржи помечены в интерфейсе значком **◆** (в чипсах
фильтра), бейджем **DEX** (в колонке «Биржа») и подписью **(DEX)** в форме
алерта — так сразу видно, что инструмент торгуется на децентрализованной
площадке. Что именно проверялось и какие у бирж особенности — в
[`EXCHANGES.md`](EXCHANGES.md).

```
┌──────────────┐   WebSocket    ┌───────────────┐    WS push     ┌──────────────┐
│ 11 бирж      │ ─────────────► │ collector     │ ─────────────► │ браузер      │
│ spot + perp  │   ccxt.pro     │ (asyncio)     │   1 раз/сек    │ карта/таблица│
└──────────────┘                └───────┬───────┘                └──────────────┘
      ▲                                 │
      │ REST (тикеры, свечи, OI)        ▼
      └────────────────────────── Store (in-memory) ──► filters ──► alerts ──► Telegram
```

## Как запустить

### Windows — самый простой путь

Двойной клик по **`start.bat`** (или в PowerShell:
`powershell -ExecutionPolicy Bypass -File .\start.ps1`).

Скрипт сам найдёт Python, установит зависимости и предложит меню:

| Пункт | Что делает | Память |
|---|---|---|
| **1. ДЕМО** | данные из записанного снимка рынка, интернет не нужен | ~150 МБ |
| **2. ДИАГНОСТИКА** | проверяет, почему биржи не подключаются | — |
| **3. LIVE лёгкий** | 4 биржи: Binance Futures, Bybit, OKX, Gate.io | ~400 МБ |
| **4. LIVE полный** | все 8 бирж, включая MEXC, Aster, Hyperliquid | 2–3 ГБ |
| **5. LIVE с прокси** | если биржи блокируют регион | ~400 МБ |

Браузер откроется сам на <http://localhost:8000>.

**Начните с пункта 1** — он работает без интернета и без бирж, так что интерфейс
вы увидите сразу. Пункт 2 стоит запустить, если live-режим не получает данные.

### Зависимости

**Через `start.bat` / `start.ps1` устанавливать ничего не нужно** — запускальщики
проверяют окружение сами и при необходимости ставят пакеты.

При запуске вручную — нужны:
```powershell
python -m pip install -r requirements.txt
```

Проверка не наивная (`import ccxt` и готово), а через `app/preflight.py`:

| Что проверяется | Почему недостаточно простого импорта |
|---|---|
| наличие пакетов | — |
| **минимальные версии** | `import ccxt` проходит и на 4.1.x, а классов `aster`/`hyperliquid` там нет — биржа молча не подключится |
| **наличие классов бирж** в `ccxt.pro` | то же самое: версия может формально подходить, а нужной биржи нет |
| `protobuf` | без него WebSocket MEXC сыплет `NotSupported` — это **предупреждение**, не блокировка |
| `certifi` | на Windows без него возможны ошибки проверки сертификатов |
| `orjson` | необязательный: сериализация WS-пуша в 3–9 раз быстрее stdlib json; без него работает встроенный fallback |
| extras у `uvicorn[standard]` | влияют на скорость, не на запуск (на Windows `uvloop` не нужен в принципе) |

`run.py` прогоняет эту проверку **до** импорта тяжёлых модулей и вместо голого
traceback печатает, чего не хватает и какой командой это ставится.
Та же проверка используется в `doctor.py` (раздел 1) и в обоих запускальщиках,
так что требования не разъезжаются между тремя местами.

Проверить окружение отдельно:
```powershell
python doctor.py          # раздел 1 покажет версии и недостающее
```

### Вручную (любая ОС)

```powershell
# Windows PowerShell
cd crypto-screener
python -m pip install -r requirements.txt

$env:MODE='replay'; python run.py        # демо, без интернета
python doctor.py                          # диагностика подключения
$env:TOP_N='60'; $env:BOOKS='25'; python run.py    # live, лёгкий профиль
```

```bash
# Linux / macOS
cd crypto-screener
pip install -r requirements.txt

MODE=replay python run.py                 # демо, без интернета
python doctor.py                          # диагностика подключения
TOP_N=60 BOOKS=25 python run.py           # live, лёгкий профиль
```

Открыть <http://localhost:8000>.

> **Если `start.ps1` выдаёт `Unexpected token ')'`** — файл потерял BOM при
> пересохранении. Windows PowerShell 5.1 читает `.ps1` без BOM как cp1251,
> и кириллица ломает парсер. Лечится либо пересохранением в «UTF-8 with BOM»,
> либо запуском `start.bat` — он специально держится в чистом ASCII и работает
> при любой локали. Регрессию ловит `tests/test_encodings.py`.

Требования: **Python 3.10+**, ~400 МБ свободной памяти на лёгком профиле.
Проверить версию: `python --version`. На Windows при установке Python
обязательно поставьте галочку **«Add python.exe to PATH»**.

Первые 3–5 минут часть метрик (NATR, 1ч/4ч доходность, спайки) ещё не заполнена:
нужно скачать свечи и накопить минутные окна. Это нормально — прогресс виден
по статусу бирж в шапке.

> Фронтенд можно открыть и как обычный файл `web/index.html` — без бэкенда он
> переключится в **DEMO**-режим и сгенерирует данные сам, чтобы интерфейс был живой.

### Если биржи не подключаются

Симптом: в логе `load_markets failed` по всем биржам, сервер стартует, но
интерфейс пустой. Запустите диагностику — она покажет, на каком слое обрыв:

```powershell
python doctor.py            # или: python run.py --doctor
python doctor.py bybit okx  # только конкретные биржи
```

Подробная таблица причин и решений — в разделе
[«Если биржи не подключаются»](#если-биржи-не-подключаются) ниже.

## Что умеет

| Раздел | Что показывает |
|---|---|
| **Графики** (стартовая вкладка) | **Сетка живых свечных графиков**, как в оригинале: 1–16 ячеек (кнопки 1/2/4/6/9/12/16), таймфреймы 1м/5м/15м/1ч, выбор биржи или «Все». В каждой ячейке — свечи, объём, цена, бейдж изменения за 24ч, маркер спайка ⚡. Двойной клик или кнопка ⤢ открывает карточку инструмента с большим графиком и плотностями. Свечи обновляются сами раз в 15 с + последняя свеча дёргается от каждого тика |
| **Карта рынка** | Плитки: цвет = изменение за 24ч, размер = объём, ⚡ = спайк. Клик → карточка инструмента |
| **Скринер** | Таблица с 20 метриками: цена, Δ за 1м/5м/15м/1ч/4ч, диапазон, NATR, объём, сделки, дельта, CVD, дисбаланс стакана, funding, OI, спайки. Подсветка цены на каждой сделке |
| **График монеты** | Свечи + объём на 6 таймфреймах (1м/5м/15м/1ч/4ч/1д), зум колесом, панорама drag'ом, перекрестье с OHLCV-тултипом. Поверх свечей — **линии плотностей стакана** (толщина ∝ объёму заявки) и **маркеры спайков**. Последняя свеча обновляется live из общего WS-потока. Открывается из любой точки: плитка карты, строка таблицы, строка плотностей, тост алерта |
| **Плотности** | Крупные лимитные заявки в стакане по всему рынку: цена, расстояние от последней цены, объём в $, число заявок, сторона |
| **Фокус-режим** | Одна биржа + один рынок + top-N (50) монет **по вашему фильтру**: стримы держатся только на них, отбор перепроверяется каждые 15 с, остальные биржи ставятся на паузу. Таблица скринера при этом показывает всю биржу |
| **Алерты** | Правила по любой из 20 метрик: «на пересечении» или «пока истинно», cooldown, область (биржа/рынок/подстрока символа), доставка в UI и Telegram |

График написан на canvas вручную (~450 строк), без внешних библиотек: TradingView
lightweight-charts тянется с CDN и не работает ни офлайн, ни в песочнице
предпросмотра. Свой рендерер заодно позволяет рисовать плотности и спайки
поверх свечей — то, ради чего скринер и делается.

**Фильтры** (22 штуки, все комбинируются): диапазоны по движению на 6 таймфреймах,
волатильности (NATR), объёму, числу сделок, дельте, CVD, дисбалансу, funding, OI;
флаги «есть спайк», «есть крупная плотность», «только зелёные/красные»,
«независимые инструменты» (монета торгуется только на одной бирже).

**Пресеты** — готовые наборы под типовые задачи: «Монеты в игре», «Пробой/всплеск»,
«Максимальная волатильность», «Проливы», «Отрицательный фандинг»,
«Неэффективности (независимые)», «Крупные плотности».

## Фокус-режим: одна биржа + один рынок + top-N по фильтру

Полный профиль стримит ~10 500 инструментов на 12 коллекторах. Это честно, но
дорого: WS-пуш сериализует тысячи строк раз в секунду, а `/api/grid` заказывает
свечи у биржи для монет, которых в горячем наборе может и не быть. На живом
замере сетка из 9 графиков собиралась **21 секунду** — ровно то, что выглядит
как «графики не грузятся».

Фокус-режим делает обратное: **стримится только то, что вы смотрите**.

* чипсы бирж переходят в одиночный выбор (одна биржа), тумблер рынка — один рынок;
* раз в `interval` секунд (дефолт 15) отбор пересчитывается: top-`limit`
  (дефолт 50) монет **по текущему фильтру** — объём, NATR, дельта, фандинг,
  спайки, что угодно из каталога фильтров;
* подписки сужаются **сразу** в момент включения: сначала применяется
  предварительный отбор по тикерам (ноль запросов к бирже), а точный отбор по
  свечам лишь меняет состав следом — статус честно пишет «предварительный
  отбор — свечи уточняют состав»;
* на отобранные монеты заводятся тикеры/сделки/стаканы, с остальных подписка
  снимается и на стороне биржи (`un_watch_*`);
* прочие биржи ставятся на паузу (галочка «остальные биржи на паузу»): тяжёлые
  потоки закрываются, опрос тикеров замедляется до 120 с;
* `/api/grid` берёт ячейки из этого же отбора, а WS-пуш шлёт только его —
  поэтому графики и таблица обновляются мгновенно.

Первый пересчёт занял 6.5 c (запросы свечей к Binance ~1.2 c каждый), остальные —
из кэша; пока свечи добираются, UI честно пишет «у N монет свечи ещё не
загружены — отбор уточнится в следующие проходы».

### Как это устроено внутри

**Конвейер отбора: мгновенный → дешёвый → точный.** Часть метрик (NATR,
Δ за 1м/5м/15м) считается из 1m-свечей, а свечи мы держим только для горячего
набора. Ранжировать «по волатильности» весь рынок, не скачав свечи, физически
нельзя, поэтому:

0. **мгновенная ступень (предварительный отбор)** — при включении фокуса
   подписки сужаются по одним тикерам: применяется дешёвая часть фильтра
   (`vol_min`, `chg`, `fund`, …) и ранжирование прокси-метрикой (для NATR —
   диапазон 24ч, для Δ — изменение 24ч, обе из тикеров). Ноль запросов к
   бирже: состояния «стримит всё, пока думает» больше нет;
1. **дешёвый уровень** — пул кандидатов (`limit × 3…12`, не больше 600):
   вселенная предварительно режется дешёвой частью фильтра (монеты, которые
   заведомо не пройдут, не заказывают свечи вовсе), затем ранжируется
   прокси-метрикой, а не объёмом — топ по объёму для фильтра волатильности
   это мейджоры с низким NATR, и пул раздувался до 600 кандидатов;
2. **точный уровень** — кандидатам добираем 1m-свечи и уже по ним применяем
   полный фильтр и финальную сортировку. Точный отбор заменяет предвари-
   тельный сразу, как готов (strict-ротация).

Пока свечи не доехали, пустой промежуточный результат **не применяется** —
подписки остаются на предварительном отборе и не скачут в полный горячий
набор и обратно. Если фильтр узкий и кандидатов не хватило, пул расширяется
ступенями 3× → 6× → 12×, а в статусе появляется «фильтру соответствует K монет
(просмотрено P из U)» — молча отдать пустую сетку нельзя.

Замер схемы отбора (`tools/bench_focus_select.py`, вселенная 500 инструментов,
пресет «Максимальная волатильность»): запросов свечей до первого отбора
**500 → 150 (3.3×)**, сужение подписок — после всего отбора (~25 c на живой
бирже) → **сразу** (предотбор по тикерам, 0 запросов), качество отбора то же.

**Скорость бирж определяет бюджет.** Замер REST-таймингов (таблица в
[`EXCHANGES.md`](EXCHANGES.md)): `fetch_tickers(None)` на всю биржу стоит
0.16–0.46 c даже у MEXC с 1216 инструментами — поэтому «дешёвый» уровень отбора
бесплатен. А вот `fetch_ohlcv` у MEXC занимает **5.78 c** против 0.70 c у Binance:
на медленных биржах отбор по волатильности добирается несколькими фоновыми
проходами, и UI это показывает, а не притворяется, что результат окончательный.

**Одна монета = одна строка отбора.** На Binance Futures торгуются и `BTC/USDT:USDT`,
и `BTC/USDC:USDT`: без дедупликации по базовому активу в «top-50» попадали два BTC
и два ETH (первые 10 строк замера до фикса: `BTC, ETH, BTC, ETH, SOL, …`), то есть
реально 40 монет вместо 50, а сетка рисовала одну монету дважды. Галочка
«одна монета = одна строка отбора» это выключает/включает.

**Бюджет добора свечей.** Один `fetch_ohlcv` у Binance занимает ~1.2 c (замер),
поэтому 240 кандидатов — это десятки секунд. Интерактивный пересчёт (когда вы
нажали кнопку) ограничен 5 секундами и 60 запросами: отдаём best-effort, помечаем
«уточняется», а фоновые проходы каждые 15 с добирают остаток (свечи кэшируются
на 60 с). Без этого `POST /api/focus` висел бы 9–13 c и упирался в 12-секундный
таймаут фронтенда.

**Strict-ротация.** Отбор жёсткий: выпал из top-50 — подписки сняты сразу,
«липкого» набора нет. Возврат в топ возвращает стрим (проверяется тестом).

**Пустой отбор не маскируется демо-данными.** Если под фильтр ничего не
нашлось (или биржа не подключилась), сетка рисует заглушку с текстом
примечания сервера, а не синтетические свечи: `demoGrid()` подставляется только
когда ответа нет вовсе (см. `BUGFIXES.md`, п.42).

### Что НЕ сжимается в фокус-режиме

Таблица скринера и карта рынка показывают **всю выбранную биржу**: REST-срез
тикеров стоит один запрос на биржу, поэтому «просеять весь рынок» по-прежнему
можно. WS-пуш при этом остаётся узким — фронтенд сам просит полную базу через
`GET /api/screener` и подмешивает в неё живые тики из пуша (флаг `base` в
сообщении `filters`). Без этого разделения «сжать пуш» означало бы «сжать и
таблицу до 50 строк».

### Грабли, которые пришлось выловить замерами

* **Потерянное пробуждение.** Сигнал «список изменился» сбрасывался при входе в
  сон, и если он приходился на момент, когда ротация занята подписками, следующий
  пересчёт случался только через 45 c. После выключения фокуса биржа ещё минуту
  стримила прежние 50 монет.
* **Последовательные отписки.** Переход 150 → 50 подписок требовал ~170 вызовов
  `un_watch_*` по ~0.3 c каждый: ротация залипала на **56 секунд**. Вынесено в
  фоновую задачу с параллельным исполнением. Та же болезнь сидела и в ветке
  «биржа на паузу» (`_close_streams`): из-за неё Binance возвращался к полному
  набору на ~40 секунд позже, чем нужно.
* **Устаревший пересчёт после выключения.** Пересчёт по NATR шёл 13 c; если за
  это время выключить фокус, завершившийся пересчёт снова ставил биржи на паузу.
  Лечится счётчиком «поколения» параметров и проверкой после каждого долгого шага.

Все три случая закрыты регрессионными тестами (`tests/test_focus.py`), а полное
описание с логами — в [`BUGFIXES.md`](BUGFIXES.md), п.33–43.

Воспроизвести замер на своих биржах:

```bash
EXCHANGES=binanceusdm,bybit,mexc MARKETS=swap TOP_N=150 BOOKS=30 python run.py &
SRVPID=$! BASE=http://127.0.0.1:8000 python tools/measure_focus.py
```

### Про объёмы и типы контрактов

Самая частая ошибка в самописных скринерах — пересчёт объёмов. Здесь правило единое
и проверено на живых данных:

| Рынок | Формула USD-оборота | Проверка |
|---|---|---|
| Bybit linear `BTC/USDT:USDT` | `quoteVolume` | $6.39B |
| Bybit inverse `BTC/USD:BTC` | `baseVolume · contractSize` | $224M ≈ `turnover24h` 2663 BTC · цена |
| OKX linear `BTC/USDT:USDT` | `baseVolume · contractSize · price` | $8.16B (`quoteVolume` биржа не отдаёт) |
| OKX inverse `BTC/USD:BTC` | `baseVolume · contractSize(100)` | $582M ≈ `volCcy24h` 6925 BTC · цена |

У инверсных контрактов `amount` уже номинирован в USD, поэтому умножать его на цену
нельзя — иначе получается `price²` и «плотности» в триллион долларов.

### Про funding и OI

Вместо N запросов по символу используются bulk-эндпоинты — один вызов на всю биржу:

- **Bybit** — `v5/market/tickers?category=linear`: OI, OI в USD, funding и turnover сразу
- **OKX** — `v5/public/open-interest?instType=SWAP`: OI по всем 495 контрактам
- **Binance** — `fapi/v1/premiumIndex`: funding по всем ~900 контрактам;
  OI bulk-эндпоинта нет, поэтому добирается точечно по топ-40 с семафором

## Если биржи не подключаются

Симптом: в логе `load_markets failed` по всем биржам сразу, сервер стартует,
но интерфейс пустой.

**Первым делом:**
```bash
python doctor.py                  # или: python run.py --doctor
python doctor.py --quick          # только сеть, без медленного слоя ccxt
python doctor.py bybit okx        # только конкретные биржи
python doctor.py --timeout 3      # короче таймауты, если сеть «висит»
```

Диагностика разделяет **трафик и DNS** — это разные поломки с разными
лекарствами, и путать их дорого:

| Слой | Что проверяет |
|---|---|
| a) TCP по IP-литералу | `1.1.1.1:443`, `8.8.8.8:443`, `104.16.0.1:443` — есть ли исходящий трафик **вообще**, DNS не участвует |
| b) системный DNS, 4 нейтральных домена | работает ли резолвер в принципе |
| c) системный DNS, хосты бирж | блокируются ли **именно биржи** |
| d) прямой DNS-запрос к 1.1.1.1/8.8.8.8 | кто виноват: локальная машина или вышестоящий DNS |

Слой (d) реализован собственным UDP-клиентом (`app/netprobe.py`, ~150 строк,
без зависимостей). Он нужен потому, что системный `getaddrinfo` проходит через
файл hosts, кэш службы DNS и веб-экран антивируса, а прямой запрос — нет.
Если публичный DNS домен находит, а системный нет, — виновата локальная машина,
и VPN не нужен.

Матрица вердиктов:

| TCP | Нейтральный DNS | DNS бирж | Вердикт | Что делать |
|---|---|---|---|---|
| FAIL | — | — | `no_network` | кабель / Wi-Fi / файрвол / VPN |
| OK | FAIL | — | `dns_dead` | сменить DNS на 1.1.1.1, `ipconfig /flushdns` |
| OK | OK | FAIL | `exchange_dns_blocked` | выборочная блокировка: DNS или VPN |
| OK | OK | частично | `partial_dns` | запускать с `EXCHANGES=` только рабочих |
| OK | OK | OK | `net_ok` | проблема выше DNS: геоблок (403/451), TLS, порт 443 |

При вердикте `no_network` медленный обход бирж пропускается: каждая висела бы
до таймаута, и вы ждали бы минуты ради заведомо известного ответа.

Каждый шаг печатается по мере выполнения. При мёртвой сети полный прогон
занимает десятки секунд на таймаутах — это работа, а не зависание; для быстрой
оценки используйте `--quick`.

Диагностика идёт по слоям и показывает, где именно обрыв:

| Слой | Что проверяет | Типичная причина падения |
|---|---|---|
| 1. Окружение | версии Python, ccxt, aiohttp/yarl, certifi, protobuf, прокси-переменные **и системный прокси Windows (реестр)** | не установлен пакет; включён прокси VPN-приложения |
| 2. DNS | резолв хостов бирж | нет интернета, кэш DNS, VPN с утечкой |
| 3. TLS | рукопожатие с `api.binance.com` | сертификаты (часто на Windows) |
| 4. HTTPS | прямой запрос к каждой бирже **через urllib** | файрвол, антивирус, геоблок |
| 4b. aiohttp | тот же запрос **транспортом ccxt**, напрямую и через прокси; при DNS-провале — контрольный зонд через системный резолвер | системный прокси (urllib его использует, aiohttp — нет), TLS-перехват, aiodns |
| 4c. DNS-резолверы | системный `getaddrinfo` против асинхронного `aiodns` (прямые UDP-запросы к DNS-серверу) | антивирус/файрвол/VPN/DoH блокируют прямой UDP мимо службы DNS Windows |
| 5. ccxt | `load_markets()` по каждой бирже (с учётом `PROXY_URL` и DNS-резолвера, как в run.py) | версия ccxt, особенности биржи |

Разделение слоёв 4, 4b и 5 принципиально: urllib на Windows ходит через
**системный прокси из реестра** (его включают VPN-приложения — Clash, v2rayN,
Outline и т.п.), а ccxt/aiohttp подключается напрямую. Комбинация «шаг 4 OK,
шаг 5 FAIL мгновенно на всех биржах» означает именно этот раскол — и шаг 4b
подтверждает его, показывая, через какой прокси запрос проходит. Лечение:
`$env:PROXY_URL="http://127.0.0.1:PORT"; python run.py` (адрес PORT виден
в шаге 1 и в Параметрах Windows → Сеть и Интернет → Прокси-сервер).

У той же комбинации «шаг 4 OK, шаг 5 FAIL» есть и вторая причина — шаблон
`ClientConnectorDNSError … Could not contact DNS servers` в цепочке
`__cause__`. Так выглядит заблокированный **aiodns**: при его наличии
(старые ccxt ставят его обязательно) aiohttp резолвит домены прямыми
UDP-запросами к DNS-серверу адаптера, минуя службу DNS-клиента Windows, —
антивирус, файрвол, VPN или «шифрованный DNS» (DoH) этот путь часто режут,
а системный резолвер (браузер, urllib, шаги 1–4) продолжает работать.
Шаг 4c ловит раскол напрямую, 4b подтверждает контрольным зондом. Лечится
автоматически: `apply_dns_resolver()` переключает aiohttp на системный
`ThreadedResolver` (см. ниже).

**Частные случаи:**

| Что в логе | Причина | Решение |
|---|---|---|
| Падают **все** биржи сразу, HTTP-слой тоже | исходящий трафик блокируется | файрвол/антивирус; попробуйте раздачу с телефона |
| Шаг 4 OK, шаг 5 — `ExchangeNotAvailable` за 0.3 c на всех биржах | системный прокси Windows: urllib через него ходит, ccxt — напрямую | `$env:PROXY_URL="http://127.0.0.1:PORT"; python run.py` |
| `← ClientConnectorDNSError … Could not contact DNS servers` на всех биржах при зелёных шагах 1–4 | aiodns шлёт DNS-запросы прямым UDP мимо службы DNS Windows, и их блокируют (антивирус/файрвол/VPN/DoH) | уже чинится автоматически (`DNS_RESOLVER=threaded` по умолчанию); при желании: DNS 1.1.1.1, отключить DoH, `ipconfig /flushdns` |
| `← ClientConnectorSSLError … CERTIFICATE_VERIFY_FAILED` (после `←` — настоящая причина из `__cause__`) | TLS-перехват: антивирус подменяет сертификаты | отключить проверку HTTPS в антивирусе; `pip install -U certifi` |
| `HTTP 403` / `451` / `restricted` | биржа блокирует регион | VPN, либо `HTTPS_PROXY` (см. ниже) |
| `getaddrinfo failed` | DNS | смените DNS, перезапустите роутер |
| `mexc requires protobuf` | WebSocket MEXC в protobuf | `pip install protobuf==5.29.5` (уже в requirements) |
| `timed out` / `actively refused` / `forcibly closed` | файрвол или прокси | разрешите исходящие на 443 |
| `InvalidProxySettings: multiple conflicting proxy settings` | задано несколько способов прокси сразу (например, `httpProxy` и `httpsProxy`) | используйте только `PROXY_URL` — приложение само разложит его в `httpsProxy` (REST) + `wssProxy` (WS) |
| Тикеры работают, а сделок/стаканов нет | прокси применён только к REST | задайте `PROXY_URL` — он покрывает и WebSocket |

**Прокси** поддерживается из коробки — просто задайте переменную:

```powershell
$env:HTTPS_PROXY="http://127.0.0.1:1080"; python run.py    # PowerShell
```
```bash
HTTPS_PROXY=http://127.0.0.1:1080 python run.py             # bash
```
или явно (имеет приоритет над переменными окружения):
```bash
PROXY_URL=http://127.0.0.1:1080 python run.py
```

Тонкость, из-за которой прокси часто «не работает»: сам ccxt на aiohttp
переменную `HTTPS_PROXY` **не читает** (`aiohttp_trust_env` по умолчанию `False`).
А даже если включить этот флаг, он влияет только на REST — для WebSocket ccxt
идёт отдельным путём, через `check_ws_proxy_settings()` и атрибуты
`wsProxy`/`wssProxy`/`wsSocksProxy`. То есть тикеры пошли бы через прокси, а
потоки сделок и стаканов легли бы напрямую.

Вторая тонкость: ccxt требует **ровно одну** настройку прокси на слой — если
задать и `httpProxy`, и `httpsProxy` вместе, любой запрос упадёт с
`InvalidProxySettings: multiple conflicting proxy settings`.

Поэтому `apply_proxy()` в `app/collector.py` раскладывает один адрес так:
`httpsProxy` (REST — все URL бирж https, ccxt передаёт значение в aiohttp
`proxy=`) + `wssProxy` (WebSocket — потоки wss) + `aiohttp_trust_env` как
страховка для окружения. При старте в лог пишется
`используется прокси … (REST: httpsProxy, WS: wssProxy)`. Сквозная проверка —
`tools/devproxy.py` (мини CONNECT-прокси): через него прогнаны и `load_markets`,
и `watch_ticker`.

Если PROXY_URL не задан, а в Windows включён **системный прокси** (его
прописывают VPN-приложения), коллектор один раз предупредит в лог: браузер и
urllib ходят через него, ccxt — напрямую, и это частая причина «все биржи
ExchangeNotAvailable за 0.3 c». Лечение — `$env:PROXY_URL="http://127.0.0.1:PORT"`
(адрес виден в `doctor.py`, раздел 1).

**DNS-резолвер.** По умолчанию приложение переключает aiohttp на системный
резолвер Windows (`apply_dns_resolver()` → `ThreadedResolver`, переменная
`DNS_RESOLVER=threaded`). Дефолт aiohttp при установленном aiodns
(`AsyncResolver`) резолвит домены прямыми UDP-запросами к DNS-серверу
адаптера, минуя службу DNS-клиента, — на Windows этот путь регулярно
блокируют антивирус/файрвол/VPN/DoH, и все биржи падают с
`ClientConnectorDNSError: Could not contact DNS servers` при полностью
работающем интернете. Системный резолвер использует тот же путь, что
браузер и urllib, поэтому работает всегда, когда работает сеть; хостов
у приложения десяток, разницы в скорости нет. Патч покрывает и REST, и
WebSocket (WS ccxt ходит через ту же aiohttp-сессию). Вернуть дефолт
aiohttp, если он вам зачем-то нужен: `DNS_RESOLVER=aiodns` в `.env`.
Диагностика: `python doctor.py`, разделы 4b (контрольный зонд) и 4c
(сравнение резолверов в лоб).

### Сколько это ест ресурсов

`TOP_N` — главная ручка. Физически стримить 18 000 инструментов нельзя и не нужно:
нужны «монеты в игре», а они почти всегда в топе по объёму.

| Профиль | Коллекторов | WS-подписок | RSS (плато) | Что проверено |
|---|---|---|---|---|
| `MARKETS=swap TOP_N=25 BOOKS=10` | 7 | ~245 | **~500 МБ** | только фьючерсы |
| `TOP_N=20 BOOKS=8` | 12 | ~340 | **~660 МБ** | спот+фьючерсы, 4 биржи |
| `TOP_N=25 BOOKS=10` | 8 | ~280 | **~660 МБ** | 6020 инструментов, $169B, 2 ошибки за 3 мин |
| `TOP_N=50 BOOKS=20` | 8 | ~560 | **~790 МБ** | 6020 инструментов, рост выходит на плато |
| `TOP_N=60 BOOKS=25` | 3 | ~330 | ~300 МБ | 2100 инструментов, ~5k WS-сообщений/мин |
| `TOP_N=300 BOOKS=80` (дефолт) | 8 | ~3500 | **нужно 2–3 ГБ** | не замерялось целиком |

**Память — главное узкое место**, и распределяется она неочевидно:

| Потребитель | Доля | Комментарий |
|---|---|---|
| Метаданные рынков ccxt | ~380 МБ на 8 биржах | ccxt грузит ВСЕ типы рынков: у Gate 7166 объектов при 1025 свопах. Режется `options.fetchMarkets` (OKX: 4389 → 500) |
| История цен | ~69 МБ на 6000 символов | `RingBuffer` на `array('d')`; с `deque[tuple]` было бы ~1075 МБ |
| Кэш сделок ccxt | ~120 МБ при `tradesLimit=1000` | снижен до 200 — нам нужно лишь не потерять сделки между вызовами `watch_trades` |
| Стаканы | ~9 МБ на 160 книг | MEXC игнорирует `limit` и шлёт ~1500 уровней |

Ошибки в основном не наши: Gate стабильно отказывает по стакану для части
символов (`龙虾/USDT:USDT`). На такие случаи есть автоматический выключатель —
после 5 не-сетевых отказов подряд поток гасится, символ больше не
переподписывается, а раз в 10 минут объявляется амнистия. Если же забанено
≥50% стаканов биржи, это трактуется как ошибка конфигурации (невалидный
`book_limit`), а не как плохие символы: бан снимается и пишется `ERROR`
(подробности в `EXCHANGES.md`, п.10, и `BUGFIXES.md`, п.24).

**Фокус-режим — самый дешёвый способ смотреть графики:** 3 биржи × `TOP_N=150`
дали 489 МБ RSS и 450 подписок; включение фокуса (Binance/swap, top-50, прочие
биржи на паузу) снизило подписки до 50 и ускорило сетку графиков с 21 c до 0.13 c
при тех же 492 МБ. Память почти не меняется — её съедают метаданные рынков ccxt,
а не потоки; зато event loop разгружается, и свечи перестают висеть.

**Горячая ротация:** раз в 45 сек топ пересчитывается; монета, выросшая в объёме,
получает стримы, протухшая — теряет их, причём подписка снимается и на стороне биржи
(`un_watch_*`). Без этого список подписок растёт бесконечно и соединение деградирует.

**WS-подписки — батчевые** (см. `BUGFIXES.md`, п.49): на биржах, где ccxt умеет
`watch_*_for_symbols` (binance, bybit, okx, gate-сделки, aster) и `watch_tickers`
(все), вместо задачи на символ живёт одна задача на чанк ≤100 символов — это
~320→3 корутины на биржу, а у Binance ещё и ~50→3 WS-соединения (ccxt строит их
URL из списка символов). Где батчей нет (mexc/hyperliquid-сделки, gate-стаканы)
или где батч стабильно отказывает, автоматически включается прежний поточечный
режим с баном отдельных символов. Живая карта подписок — `GET /api/perf → ws_streams`.

## Тесты

```bash
pip install pytest httpx
pytest tests/ -q        # 327 тестов (+1 skip, если DEX-биржи не подключены)
```

Тесты не абстрактные: в них зашиты конкретные числа с живых бирж и регрессии
на баги, которые действительно были найдены и починены (см. `BUGFIXES.md`).

**Статический аудит связки HTML ↔ JS ↔ CSS** — ловит поломки, которые не видны
ни в консоли, ни в интеграционных тестах:

```bash
python tests/audit_frontend.py
```

| Что сверяет | Почему это важно |
|---|---|
| Каждый ID, к которому обращается JS, существует в HTML | `$("#foo")` вернёт `null` и фича молча отвалится |
| `colspan` каждой таблицы = числу её колонок | иначе пустая строка/заглушка съедет |
| `<th>` в шапке = `<td>` в шаблоне строки | иначе поедут колонки |
| Кнопкам вкладок соответствуют секции | иначе вкладка не переключится |
| Таймфреймы графика известны бэкенду | иначе кнопка даст HTTP 400 |
| В карточке есть canvas, заглушка, кнопки ТФ, легенда | график должен быть в разметке |
| `chart.js` подключён **до** `app.js` | иначе `CandleChart` будет `undefined` |
| Нет внешних ресурсов (`http://…`) | иначе офлайн и песочница предпросмотра сломаются |
| Поля, которые читает UI, есть в выдаче API | иначе в ячейках будет `undefined` |

Аудит встроен в pytest и **проверен на мутациях**: тест специально ломает копию
фронтенда пятью способами (убирает `chart.js`, добавляет несуществующий
таймфрейм, удаляет колонку, портит ID, вставляет внешний CSS) и требует, чтобы
аудит на каждом из них упал. Без этого «проблем не найдено» ничего не значило бы —
проверка, которая никогда не срабатывает, бесполезна.

**Смоук-тест фронтенда** (опционально, нужен jsdom) — запускает настоящие
`index.html` + `app.js` в DOM и проверяет рендер всех четырёх разделов:

```bash
npm i jsdom ws                                    # в любую папку
MODE=replay python run.py &                       # поднять бэкенд
NODE_PATH=/путь/к/node_modules BASE=http://127.0.0.1:8000 \
  node tests/smoke_frontend.js
```

В `data/replay_snapshot.json` лежит реальный снимок рынка, поэтому `MODE=replay`
показывает настоящие цены и объёмы без подключения к биржам — удобно для
разработки интерфейса.

Проверок во фронтенд-смоке **94**: рендер всех четырёх разделов, построение
фильтров из `/api/meta`, пресеты, поиск, сортировка кликом, карточка инструмента,
график, биржи и фокус-режим.

Отдельный смоук **без бэкенда** — проверяет, что фокус-режим работает и в
DEMO-фолбэке (файл открыли напрямую, сервер не запущен):

```bash
NODE_PATH=/путь/к/node_modules WEB=web node tests/smoke_focus_demo.js
```

Что проверяется отдельно:

- **Биржи и DEX-метки.** Тест сверяется с тем, что объявил бэкенд
  (`/api/meta → exchange_info`), а не с жёстким списком — поэтому он проходит
  при любом `EXCHANGES=...`. Проверяет, что каждая заявленная биржа видна как
  чип, что DEX помечены ◆, а CEX — нет, и что форма алерта подписывает DEX.
- **Сетка графиков**: стартовая вкладка, ячейки с canvas и свечами,
  тумблер спот/фьючерсы, пересчёт колонок при смене размера сетки
- **Фокус-режим** — самая свежая секция, и каждая проверка в ней появилась
  после реально пойманного бага:
  * тумблер включает режим, лимит берётся из поля, панель раскрывается;
  * чипс биржи **заменяет** выбор, а не добавляет (и гаснуть при повторном
    клике не должен — иначе в фокусе останется ноль бирж);
  * сетка графиков переключается вместе с чипсом (иначе биржу сменили,
    а ячейки остались от прежней);
  * в фокусе нет кнопки «Все»;
  * **таблица скринера не сжимается** до top-N (150 строк при лимите 20);
  * пресет «Максимальная волатильность» доезжает до серверного отбора, и
    отобранные монеты действительно имеют `NATR ≥ 1` — проверка сверяет ключи
    отбора с REST-выдачей, а не с тем, что нарисовал UI;
  * после выключения **сервер** тоже вышел из фокуса (`GET /api/focus →
    enabled=false`) и WS-пуш снова широкий. Именно эту пару проверок баг
    «выключение не доходило до сервера» пережил бы молча
- **Фактическую видимость**, а не атрибуты: `getComputedStyle(...).display === "none"`
  для закрытой карточки и оверлея загрузки (атрибут `hidden` однажды оказался
  перекрыт авторским `display:flex` — тест, проверявший атрибут, это пропустил)
- **График из всех четырёх точек входа** — строка таблицы, плитка карты рынка,
  строка плотностей. Для каждой проверяется не только факт открытия, но и
  `source=exchange`: то есть свечи пришли **с биржи**, а не из демо-заглушки
  (её длина — нестандартные 187 свечей, спутать нельзя).
- **Целостность свечей** — `high ≥ max(open, close)`, `low ≤ min(open, close)`,
  объём неотрицательный, метки времени упорядочены, шаг соответствует ТФ.
- **Рендер действительно рисует** — считается число вызовов `fillRect`/`stroke`/
  `fillText` на 2D-контексте. Canvas в jsdom отсутствует, поэтому контекст
  подменяется recording-mock'ом: тест проверяет логику отрисовки, не тянув
  нативный `node-canvas`.

## Производительность: что тормозило и что с этим сделали

Симптом: «тормозит всё» — таблица дёргается, графики обновляются рывками,
WS-пуш отстаёт. Причина почти всегда одна: **event loop сервера захлёбывается**,
и тогда отстают сразу все задачи (пуш, REST, алерты). Замер
(`python tools/bench_perf.py`, синтетика на 6000 символов) показал, куда
уходит CPU, — и эти места починены:

| Горячая точка | Было | Стало |
|---|---|---|
| Пересчёт плотностей/имбаланса на КАЖДЫЙ апдейт стакана (~350 мкс × 510 книг × 10 Гц) | ~1.6 ядра | троттлинг тяжёлой части до 4 Гц на символ (`BOOK_DENSITY_INTERVAL=0.25`): **2.8×** меньше CPU; стакан и bid/ask по-прежнему обновляются каждый тик |
| `ret()` — линейный скан истории цен, 30 000 вызовов/с | O(n) на вызов | бинарный поиск (`RingBuffer.bisect_ts`), O(log n) |
| `overview()` на каждый пуш каждому WS-клиенту | обход всех символов × клиенты | кэш с TTL (шапка и так обновляется раз в секунду) |
| Таблица: сравнение `td.innerHTML !== html` | браузер СЕРИАЛИЗОВАЛ DOM ~2850 ячеек/с обратно в строку | diff через JS-кэш строк: в DOM пишутся только изменённые ячейки |
| Таблица: `querySelector` на каждую переставленную строку | O(n²) обходов DOM/с при живой сортировке | Map key→`<tr>`, переиспользование без поиска |
| Карта рынка: `querySelector` × 6 на плитку (300 плиток/с) | ~1800 поисков по дереву в секунду | Map key→ссылки на детей + diff значений (стили/текст пишутся только при изменении) |
| Графики: `render()` на каждый тик | до 16 перерисовок canvas на батч, часть в один кадр | коалесцинг через `requestAnimationFrame`: максимум одна перерисовка на кадр |
| `apply_book`: нормализация 400 уровней на КАЖДЫЙ апдейт (окно троттлинга её не пропускало) | ~2 млн tuple-аллокаций/с на CORE-профиле | лёгкий путь обновляет только bid/ask; полная нормализация — вместе с тяжёлым пересчётом (4 Гц): книжный поток **575 → 414 мс CPU/с** |
| WS-пуш: `json.dumps` на клиента | 1.4 мс на payload 150 строк | `orjson` (опциональная зависимость): **0.1 мс (9.4×)**; без пакета — прежний stdlib |
| `select()` на каждого клиента каждый такт | 2–15 мс × клиенты | кэш выборки на 0.5 c по отпечатку (query, densities, restrict): одинаковые фильтры считаются один раз |
| Таблица: `void td.offsetWidth` на каждую мигнувшую цену | до 150 принудительных reflow таблицы в секунду | чередование классов `flash-up`/`flash-up-2`: анимация перезапускается без чтения layout |
| `_candles_cache` / `prevPrices` росли вечно | десятки МБ и тысячи записей за сессию | pruning: протухшее + старейшее сверх лимита (кэш свечей), чистка по видимым строкам (prevPrices) |

**Диагностика числами, а не на глаз:** `GET /api/perf` отдаёт живые метрики —
`loop_lag_ms` (главный индикатор: стабильно >50–100 → серверу тяжело),
`build_rows_ms` (сериализация всех строк), `select_ms`/`push_ms` (стоимость
пуша клиенту), счётчики WS-потоков. `python tools/bench_perf.py` — офлайн-
бенчмарк тех же операций на синтетике (сравнение «до/после» без бирж).

**Чем ещё ускориться (по убыванию эффекта):**

1. **Фокус-режим** (тумблер в UI) — стримы только на top-N отобранных монет:
   подписки 450→50, стаканы 90→30. Это самый большой рычаг: меньше WS-трафика
   и меньше пересчётов.
2. `BOOKS=30` (вместо дефолтных 20–80 на биржу) — стаканы дороже всего.
3. `TOP_N=150` — меньше символов в выборке и сериализации.
4. `PUSH_INTERVAL=2` — пуш раз в 2 секунды вдвое режет и серверный select,
   и клиентский рендер.
5. `MARKETS=swap` — не поднимать спот-коллекторы (экономит и RAM).
6. В браузере: уменьшить «Строк в таблице» (150→50) и выключить подсветку
   изменений цен (flash) — это самые частые DOM-записи.

**Регрессия:** `tests/test_perf.py` — 19 тестов: `ret()` совпадает с линейным
эталоном на случайных данных, троттлинг стакана пропускает тяжёлую часть, но
bid/ask остаются realtime, лёгкий путь не пересобирает `book` и терпит мусорные
уровни, кэш `overview()` уважает TTL, `/api/perf` отвечает всеми полями.
`tests/test_batch_ws.py` — 16 тестов батч-подписок (маршрутизация по symbol,
чанкование, отписки, fallback, авто-уменьшение чанка, pruning кэша свечей),
кэш `select()` — в `tests/test_api.py`, группировка области алертов — в
`tests/test_alerts.py`.

**Что сознательно НЕ делали** (разбор внешнего аудита с причинами отказов —
`BUGFIXES.md`, п.50): дельта-пуш и компактный массивный формат строк (приложение
локальное и однопользовательское, пуш и так ≤150 строк, а цена — протокол
версий и риск рассинхрона UI), инкрементальный `overview()` (кэш 1 c уже
закрывает стоимость), объединение `/api/symbol`+`/api/candles` (~5 мс на
localhost).

## Масштабирование

Прототип однопроцессный, состояние живёт в памяти. Что менять при росте:

1. **Store → Redis.** `STORE` уже изолирован в `app/state.py`, интерфейс не меняется.
   Это разнесёт сборщиков и API-сервер по разным машинам и даст горизонтальный масштаб.
2. **Сборщик → отдельный процесс на биржу.** `CollectorHub` уже запускает по таску
   на биржу; достаточно заменить in-process вызовы на очередь.
3. **История → TimescaleDB/ClickHouse.** Сейчас `price_hist` — deque на 900 точек
   (15 минут). Для бэктестов и истории нужны настоящие тайм-серии.
4. **Фронтенд → React.** Сейчас vanilla JS без сборки, чтобы запускать instantly.
   `app.js` разбит на независимые функции-рендеры, переносится механически.
5. **Прокси до бирж** (фича оригинала) — не реализована; добавляется на уровне
   `ExchangeConfig.options` без изменения остального кода.

## Ограничения прототипа

Честно о том, чего пока нет:

- **NATR, дисбаланс и плотности есть не у всех монет**, а только у «горячего набора»
  (`TOP_N`/`BOOKS`) — свечи и стаканы дорогие. Заполненность видна в таблице.
- **OI заполнен неравномерно**: у Bybit/Gate/MEXC/OKX есть bulk-эндпоинты → 100%,
  у Binance/Aster/Hyperliquid OI добирается точечно по топ-40 → 5–35%.
  Поднимается параметром `oi_top_n` ценой роста числа запросов.
- **Funding у Hyperliquid** заполнен на ~55%: столько контрактов отдаёт сама биржа.
- **Число сделок (`tr`)** Binance отдаёт, Bybit и OKX — нет; там будет `—`, а не `0`.
- **Спайки** появляются только через 3+ минуты работы: базе нужна медиана закрытых минут.
- **Нет аутентификации** — для локального использования. Перед публикацией нужен reverse proxy.
- **Нет хранения алертов** — правила живут в памяти процесса.
- Вотчлисты для TradingView и автонастройка прокси из оригинального сервиса не реализованы.
